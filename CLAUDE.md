# Talents-4Everyone (Talents4e)

Renamed from Build-4Everyone (Build4e, `/b4e`, `Build4eDB`) on 2026-11-02, before any release.

Exports the player's character to the wow-4e.com Build Calculator as a build code, and imports a build code to show
its talent order on the talent window while levelling (level numbers on the talents, the next one highlighted, the
order listed beside the window). The gear guide is left out for now. Rules shared by every addon (Blizzard's rules, names,
Lua 5.1, layout, TOC, CurseForge releases, the website) are in `..\CLAUDE.md`; this file holds only what is true for
Talents4e.

Stage: released; 1.0.2 tagged and pushed 2026-11-05 (first CurseForge release 0.1.0, 2026-11-02); repo J-Groove/Talents-4Everyone
(public). The windows, import, export, the planner, Settings and the minimap button work on Retail and Anniversary;
the talent order on the talent window waits for Forever itself. Releases after 0.1.0 go by tag through
`.github\workflows\release.yml` (`docs\curseforge.md`). The plan is `docs\design.md`; work in progress is
`docs\status.md`.

## Ground rules
- Git: the owner commits and pushes. Never run commit, push, merge, rebase or history rewrites, and never add a
  `Co-Authored-By: Claude` (or any Claude/Anthropic) line to a commit message. Leave changes uncommitted.
- It shows and highlights; the player clicks. It never learns talents, spends Legacy points or equips gear itself.
- Builds move in and out as the website's build codes, never a format of its own. The format is defined by
  `wow-4e\packages\core\src\build-code.ts`; the Lua encoder and decoder must agree with it, and a change there is
  made in both repos together and noted in both `docs\status.md` files.
- The talent planner follows the site's talent rules (`wow-4e\packages\core\src\talents.ts`), copied in `Rules.lua`:
  the tests check the two agree on random builds and orders, and changes go in both repos together.

## Files
In TOC load order:
- `Core.lua`: pure logic, no game calls: the build code encoder and decoder, pasted-text and item-link parsing.
- `Data.lua`: generated by `tools\make-data.mjs` from the website's game data: each class's talent node ids and the
  Legacy perk node ids per tree, in build-code order, with names, icons, rank counts, spells, rows, columns and
  prerequisites (`req`, 1-based) per talent, and the Legacy perks that move the first talent level (`early`). Never edit it by hand; run the tool after the site's data
  changes (the tests fail when the two differ).
- `Character.lua`: reads the character from the game into a build. Talents come from
  `C_ClassTalents.GetActiveConfigID()`, Legacy perks from `C_Traits.GetConfigIDBySystemID(45)`, each node read
  with `C_Traits.GetNodeInfo` by the node id `Data.lua` gives for that position. `Character.Ranks()` reads just
  the ranks, for the talent order.
- `Builds.lua`: pure logic, no game calls: the saved builds list (add, rename, delete, the 20 limit, default names,
  warnings) and which build each character follows. The windows pass in the player's class and `Name-Realm`.
- `Order.lua`: pure logic: the first talent level (Talented, from `Data.legacy[t].early`), points per level, and
  where a character stands on an order (taken steps, the next one, ranks off the build), plus the reminder's words.
  The point rules follow the site's `talents.ts` and `talent-order.ts`.
- `Rules.lua`: pure logic: the talent point rules (rows, prerequisites, ranks), checking and editing an order, and
  why a click is refused, in the site's words. A copy of the site's `talents.ts` for class talents (the Legacy
  perks' gate rule isn't copied: the planner doesn't plan perks).
- `Windows.lua`: the main window, the import box, the export box and the talent check box (`docs\ui-design.md`
  screens 1 to 3). Frames are made the first time they open. Its small helpers are shared as `ns.UI`.
- `Planner.lua`: the talent planner (screen 6), its own window opened by New plan, Edit (main window) or Edit on the
  order list. The plan's state is pure functions (tested), then the window. Saves a build or copies its link.
- `Talents.lua`: the talent order on Blizzard's talent window (screen 4): level badges, the glow on the next
  talent, and the order list docked to the window. It finds the window from a short list (`PlayerSpellsFrame`
  then the 10.x `ClassTalentFrame`) and each talent's button with `GetTalentButtonByNodeID`, falling back to
  `EnumerateAllTalentButtons`. Only our own frames, which never take the mouse over Blizzard's buttons; only
  `HookScript` and `hooksecurefunc` on Blizzard's.
- `Reminder.lua`: the level-up toast (screen 5), held back during combat and cinematics.
- `Settings.lua`: the page in Blizzard's Settings panel (screen 7), made with `Settings.RegisterVerticalLayoutCategory`
  and `Settings.RegisterAddOnSetting` (the 11.0 form, which EnhanceQoL also uses on Forever). Does nothing on a
  client without that API.
- `Minimap.lua`: the minimap button, our own (no LibDBIcon): click opens the main window, right-click opens
  Settings, drag moves it. Its icon is `Media\Icon.tga`, the site's 4E crest (owner, 2026-11-04), also the TOC's
  `IconTexture` (the addon list). Made by `tools\make-icon.mjs` from the site's `img\brand\crest.svg`; run it again
  if the crest changes. The game reads TGA or BLP, not PNG or SVG.
- `Talents4e.lua`: `/t4e` and `/talents4e` (toggle the main window) and `ADDON_LOADED`, which sets up `Talents4eDB`, the
  Settings page and the minimap button.
- `.github\workflows\release.yml` (the BigWigs packager on version tags), `tools\make-data.mjs`, `tools\make-icon.mjs`, `tools\package.ps1` (builds the CurseForge zip by hand into `.release\`), `tests\`:
  development only, left out of the CurseForge zip. Publishing steps: `docs\curseforge.md`.

## Saved data
- `Talents4eDB` (account-wide), layout in the header of `Builds.lua`:
  - `builds`: `{ id, name, code, classId, added }` per saved build, oldest first, at most 20. `code` is the site's
    build code (re-encoded on import); ids count up from `nextId` and never come back.
  - `following`: `["Name-Realm"] = id`, the build each character follows.
  - `lastExport` (code and time) and `lastCheck` (the Check talents lines).
  - `listFolded` (the order list folded to a tab), `reminderPos` (`{ point, x, y }` once the toast is dragged),
    `completed` (`["Name-Realm"] = id` once "Build complete" has been shown).
  - `settings` (the Settings page; missing means on): `minimap`, `numbers`, `list`, `reminder`.
  - `minimapAngle`: where the minimap button sits, in degrees round the minimap.

## Slash commands
`/t4e` and `/talents4e` only open and close the main window. Every feature is a button in it, never a subcommand.
- Export my character: the export box, holding a `https://wow-4e.com/builds/new#b=...` link selected for Ctrl+C.
- Check talents (footer): what the game's talent APIs return, also saved in `Talents4eDB.lastCheck`. Use it after a
  game patch.

## Website link
The Build Calculator (`/builds/new`) opens any build code from `#b=<code>`. Export gives the player that code (or
the whole `https://wow-4e.com/builds/new#b=...` link) to copy; import takes a code or link pasted from the site.
Talent and perk positions in a code follow the site's game data (`wow-4e\apps\web\public\data\v1\`), so the addon
needs the same order.

## Build codes in Lua
- The code records `Data.lua`'s game build, not the client's: positions in the code follow that data, and the site
  uses the build to spot an old layout. A client newer than the data gets a warning in the export box.
- Importing, `Builds.GameVersionAge` uses the site's layout fingerprints (`Data.layouts`, from `classes.json`) the
  way the site's `fromOldGameVersion` does: a code is old only when its class's (or the Legacy) layout changed
  since its game build, and a code from a build newer than the data gets an "update the addon" warning. When the
  site rebuilds its game data, run `tools\make-data.mjs` and release a new version (the tests fail until then).
  After a game patch, `node tools\post-patch.mjs` (or the workspace's `..\..\post-patch.ps1`, after the site's
  `npm run post-patch`) does it: rebuilds `Data.lua`, lists the talents that changed in it, checks the TOC's
  interface number against the installed Forever client and runs the tests. A new data build always needs a
  release: the released addon otherwise warns on export and calls codes from the new build "newer".
- Trees and indexes are 1-based in Lua and 0-based in the code. Bad codes raise errors; `Core.TryDecode` returns
  nil and a message for the player instead.
- The game can't say in which order talents were learned, so exports carry ranks, never an order.

## Testing
`cd tests; npm install --ignore-scripts` once, then `npm test`. The tests run the addon's Lua in wasmoon (Lua 5.4;
keep to what Lua 5.1 also has) and, when `..\..\wow-4e` is present, check `Core.lua` against the website's
`build-code.ts` on 300 random builds, `Rules.lua` against `talents.ts` on random builds and orders for every class,
and `Data.lua` against the site's game data. `Character.lua` is tested
against stubbed game APIs. wasmoon loses its globals after a few dozen `doString` calls on one engine: tests get a
fresh engine each and batch many calls with `evaluateAll`. The owner checks it in game.

Outside Forever: the TOC lists only Forever's 16001 (owner, 2026-11-02). Adding 120105 locally loads it on Retail 12.1.5 (installed in `_retail_`). There the slash
command, the windows, gear and Check talents' list of the game's own talent trees can be tried; Forever's talents
and Legacy perks can't (Retail has other node ids, other classes and no Legacy system), and a level above 60 is
written as 60 with a note. Adding 20506 loads it on Classic Anniversary 2.5.6 (`_anniversary_`, linked 2026-11-02),
only for the owner's screenshots: the windows, the planner and Settings work there, but that client has the old
talent API (`GetTalentInfo`, `PlayerTalentFrame`), not `C_ClassTalents`, so export reads no talents and the order
never reaches its talent window. The addon supports Forever only; no code for other clients (owner, 2026-11-02). Never commit or upload those numbers (`docs\curseforge.md`).
